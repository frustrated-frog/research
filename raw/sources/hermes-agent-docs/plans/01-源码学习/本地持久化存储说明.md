# 本地持久化存储说明

本文说明 Hermes Agent 在本机长期保存了哪些数据，重点回答两个问题：

- 用户对话历史、工具调用参数和工具调用结果保存在哪里。
- 除了对话历史以外，配置、凭据、技能、缓存、日志、任务调度等状态分别保存在哪里。

## 1. 根目录规则

所有主要本地状态都以 `HERMES_HOME` 为根目录：

- 如果环境变量 `HERMES_HOME` 已设置，就使用该目录。
- 如果没有设置，默认使用 `~/.hermes`。
- 如果启用 profile，每个 profile 会有独立的 `HERMES_HOME`，通常类似 `~/.hermes/profiles/<profile-name>`。

代码里应使用 `hermes_constants.get_hermes_home()` 拼接真实路径；面向用户展示时使用 `display_hermes_home()`。下面所有路径都默认相对于 `HERMES_HOME`。

## 2. 对话历史和工具调用结果

这是最容易影响测试和排障的状态面。不要只看一个 `state.db`，因为同一轮对话可能同时写入 SQLite、JSON 日志、网关 legacy transcript 或 API response store。

| 路径 | 存储内容 | 主要写入入口 | 说明 |
| --- | --- | --- | --- |
| `state.db`、`state.db-wal`、`state.db-shm` | SQLite 会话主库。包含 session 元数据、用户消息、助手回复、工具调用参数、工具调用结果、reasoning 字段、token/cost 统计、system prompt 快照、FTS 搜索索引。 | `hermes_state.SessionDB`、`run_agent.AIAgent._flush_messages_to_session_db()`、`gateway.session.SessionStore` | 当前主存储。表包括 `sessions`、`messages`、`messages_fts`、`schema_version`。工具调用结果通常以 `role='tool'` 的消息保存，工具调用参数通常在 assistant 消息的 `tool_calls` 字段里。 |
| `sessions/session_<session_id>.json` | AIAgent 原始会话快照。包含 `system_prompt`、模型、平台、启用工具列表、完整 `messages`。消息里会包含用户输入、助手输出、工具调用、工具结果、压缩摘要、todo 快照等注入消息。 | `run_agent.AIAgent._save_session_log()` | 这是“按 agent 看到的原样消息”保存，排查工具链时很有用，但也最容易包含敏感内容。 |
| `sessions/<session_id>.jsonl` | 网关 legacy transcript，一行一条消息。 | `gateway.session.SessionStore.append_to_transcript()`、`rewrite_transcript()` | 为兼容旧工具保留。新逻辑优先读 `state.db`，但 JSONL 可能保留更老的历史。 |
| `sessions/sessions.json` | 网关的 session key 到 session id 的映射，以及平台、chat/user/thread、token 统计、挂起/恢复状态等。 | `gateway.session.SessionStore` | 它不是完整聊天正文，但会影响网关如何续接同一个会话。 |
| `response_store.db` | OpenAI Responses API 兼容层的状态库。保存 response 对象、`previous_response_id` 链接所需的完整内部 conversation history、instructions、session id。 | `gateway.platforms.api_server.ResponseStore` | 用于 `/v1/responses` 的 GET、DELETE 和连续对话。这里也会保存工具调用和工具结果。 |
| `a2ui_state.db` | A2UI 页面状态库。保存 thread id、当前 `a2ui_json` 页面快照、上传图片引用、更新时间。 | `jd_a2ui.state.A2UIStateStore`、`/api/threads/{thread_id}/a2ui` | 不是通用聊天库，但会影响 `/api/chat` 的 A2UI 生成/编辑上下文。 |

### 工具调用结果到底在哪里

工具调用没有单独的“工具结果数据库”。它主要跟随对话消息一起持久化：

- 在 `state.db.messages` 中，工具结果是 `role='tool'` 的消息，字段包括 `content`、`tool_name`、`tool_call_id`。
- 在 assistant 消息中，`tool_calls` 保存工具名和参数。
- 在 `sessions/session_<session_id>.json` 中，工具调用和结果按完整消息列表原样保存。
- 在 `response_store.db` 中，Responses API 的 `conversation_history` 也会保存工具调用和结果，方便后续 `previous_response_id` 续接。
- 后台终端进程的滚动输出还可能临时/恢复性地保存在 `processes.json`。

## 3. 配置、身份和凭据

这些文件通常敏感，不能随便打包发给别人。

| 路径 | 存储内容 | 说明 |
| --- | --- | --- |
| `config.yaml` | 模型、provider、toolset、display、gateway、cron、terminal、logging 等配置。 | 主配置文件。 |
| `.env` | API Key、平台 token、provider base url、网关账号、终端后端配置等环境变量。 | 高敏文件。 |
| `auth.json`、`auth.lock` | Provider 登录态、OAuth token、托管工具网关 token 等认证信息。 | 高敏文件。 |
| `.anthropic_oauth.json` | Hermes 自己管理的 Anthropic OAuth/PKCE 凭据。 | 高敏文件。 |
| `auth/google_oauth.json` | Google/Gemini OAuth 凭据。 | 高敏文件。 |
| `google_token.json` | Google Workspace skill 的本地 token。 | 由相关 skill 脚本使用。 |
| `slack_tokens.json` | Slack 平台 token。 | 启用 Slack 时可能出现。 |
| `platforms/whatsapp/session/` 或旧路径 `whatsapp/session/` | WhatsApp bridge 登录 session。 | 里面可能有可复用登录凭据。 |
| `weixin/accounts/` | Weixin 账号登录态和上下文 token。 | 启用 Weixin 时可能出现。 |
| `feishu_comment_rules.json`、`feishu_comment_pairing.json`、`feishu_seen_message_ids.json` | 飞书评论权限规则、配对状态、消息去重状态。 | 启用飞书相关能力时出现。 |

## 4. 系统提示词、记忆、技能和插件

这些文件会影响模型“下一次启动时看到什么”，所以它们也可能造成测试或复现差异。

| 路径 | 存储内容 | 说明 |
| --- | --- | --- |
| `SOUL.md` | 默认人格/系统身份提示词。 | `ensure_hermes_home()` 会在缺失时初始化。 |
| `.skills_prompt_snapshot.json` | 技能提示词快照。 | `agent.prompt_builder` 用来缓存技能 prompt 拼接结果。 |
| `memories/MEMORY.md`、`memories/USER.md` | 文件型长期记忆。 | `tools.memory_tool` 会读写；会在新会话开始时作为冻结快照注入系统提示词。 |
| `skills/` | 用户安装、hub 安装、agent 创建或同步过来的技能。包括 `SKILL.md`、references、templates、scripts、assets 等。 | `tools.skills_tool`、`tools.skill_manager_tool`、`hermes_cli.skills_hub` 使用。 |
| `plugins/` | 用户安装插件，尤其是 memory provider 插件。 | `hermes plugins` 和 memory plugin discovery 使用。 |
| `hooks/` | 网关事件 hook。 | `gateway.hooks` 会发现并执行。 |
| `skins/`、`dashboard-themes/` | CLI skin、Web dashboard theme。 | 影响展示，不是对话正文。 |
| `shell-hooks-allowlist.json` | shell hook 允许运行记录。 | 影响 hook 是否可自动执行。 |
| `.skip_upstream_prompt` | 跳过上游提示的本地标记。 | 影响 CLI/更新流程提示。 |

## 5. 运行缓存、工具状态和附件

这些目录不一定是“聊天历史”，但经常包含工具结果、文件片段、上传附件、终端输出或浏览器状态。

| 路径 | 存储内容 | 说明 |
| --- | --- | --- |
| `processes.json` | 后台终端进程 checkpoint。包含命令、pid、cwd、退出状态、滚动输出 buffer、watch/notify 信息。 | `terminal(background=true)`、网关 watcher、崩溃恢复使用。 |
| `checkpoints/` | 文件系统自动快照。每个工作目录一个 shadow git repo，保存 `HERMES_WORKDIR`、git objects、refs 等。 | 用于 `/rollback` 或文件变更回滚。可能保存项目文件内容快照。 |
| `cache/images/`，旧路径 `image_cache/` | 消息平台下载的图片、生成图片、图片附件缓存。 | 供 vision/tool/平台发送使用。 |
| `cache/documents/`，旧路径 `document_cache/` | 消息平台下载的 PDF、docx、xlsx、zip、txt 等文档缓存。 | 远程终端后端也可能只读挂载这些缓存。 |
| `cache/audio/`、`cache/screenshots/`、旧路径 `audio_cache/`、`browser_screenshots/` | 音频、截图缓存。 | 部分工具或平台能力启用后出现。 |
| `images/` | CLI/TUI 从剪贴板粘贴的图片附件。 | 用户把图片贴进输入框时写入。 |
| `pastes/` | 大段粘贴文本折叠后的临时文件，以及 debug pending 信息。 | 大段文本可能包含源码、日志或敏感配置。 |
| `browser_auth/camofox/` | Camofox 托管浏览器 profile 身份目录。 | 用于浏览器持久化登录态。 |
| `chrome-debug/` | 本地 Chrome debug profile 数据目录。 | 用于浏览器调试/连接。 |
| `sandboxes/` | Docker/Singularity 等终端后端的本地沙箱根目录。 | 可能包含远程/隔离环境的持久文件。 |
| `modal_snapshots.json`、`singularity_snapshots.json` | 云/容器终端后端的 snapshot 映射。 | 保存 task id 到 snapshot id 的关系。 |
| `.sync.lock` | 远程后端同步回本机时的锁文件。 | 不是业务数据。 |

## 6. 日志、运行状态和网关缓存

| 路径 | 存储内容 | 说明 |
| --- | --- | --- |
| `logs/` | `agent.log`、`errors.log`、`gateway.log`、工具/debug/训练日志等。 | 日志可能包含异常栈、工具输出片段、请求摘要。 |
| `interrupt_debug.log` | 中断调试日志。 | 调试 Ctrl-C/interrupt 相关问题时出现。 |
| `gateway.pid` | 当前 gateway 进程 pid 和启动元数据。 | 用于判断 gateway 是否运行。 |
| `gateway_state.json` | gateway runtime health/status。 | 记录状态、错误、平台状态、active agents 等。 |
| `.restart_failure_counts` | gateway 重启卡死循环计数。 | 用于自动 suspend 卡住的 session。 |
| `.restart_notify.json`、`.restart_last_processed.json` | gateway restart 通知和去重标记。 | 防止重复处理平台重投递。 |
| `gateway_voice_mode.json` | gateway voice mode 状态。 | 网关语音模式使用。 |
| `.update_check`、`.update_pending.json`、`.update_exit_code` | 更新检查、更新 pending、更新退出码。 | CLI/网关更新流程使用。 |
| `channel_directory.json` | 各平台可达频道/联系人缓存。 | `send_message` 用它解析频道名。 |
| `sticker_cache.json` | Telegram sticker 的 vision 描述缓存。 | 避免重复分析同一个 sticker。 |
| `<platform>_threads.json` | 某些平台的 thread 列表缓存。 | 由平台 helper 维护。 |
| `gateway-locks/` | 平台 token scoped lock。 | 默认不在 `HERMES_HOME`，在 `XDG_STATE_HOME/hermes/gateway-locks/`；用于防止多个 profile 同时使用同一 token。 |

## 7. 定时任务和自动投递

| 路径 | 存储内容 | 说明 |
| --- | --- | --- |
| `cron/jobs.json` | 定时任务定义：任务 id、schedule、prompt、skills、deliver、next_run、运行状态等。 | `cron.jobs` 读写。 |
| `cron/output/<job_id>/<timestamp>.md` | 每次 cron 任务的本地输出。 | 即使响应用 `[SILENT]` 抑制投递，也会保留本地审计输出。 |
| `cron/.tick.lock` | tick 文件锁。 | 防止 gateway、daemon、systemd timer 同时跑 tick。 |
| `scripts/` | cron pre-run script 的允许目录。 | scheduler 只允许从该目录读取脚本，避免任意路径执行。 |

cron 任务执行时也会创建普通会话，所以结果还可能进入 `state.db` 和 `sessions/`。

## 10. 排查和清理时的判断顺序

如果怀疑“本地状态影响测试或复现”，建议按这个顺序看：

1. 先确认本次进程实际的 `HERMES_HOME`，不要假设一定是 `~/.hermes`。
2. 如果是对话串扰，优先看 `state.db`、`sessions/`、`response_store.db`。
3. 如果是系统提示词或能力表现不一致，优先看 `SOUL.md`、`.skills_prompt_snapshot.json`、`memories/`、`skills/`、`config.yaml`。
4. 如果是 A2UI 页面状态不一致，优先看 `a2ui_state.db`。
5. 如果是工具输出、终端后台任务或文件回滚异常，优先看 `processes.json`、`checkpoints/`、`logs/`、`pastes/`、`cache/`。
6. 如果是网关、平台消息或 cron 行为不一致，优先看 `sessions/sessions.json`、`cron/`、`gateway_state.json`、`channel_directory.json`、平台 session/token 文件。

排查命令示例：

```bash
HERMES_HOME_PATH="${HERMES_HOME:-$HOME/.hermes}"
find "$HERMES_HOME_PATH" -maxdepth 2 -mindepth 1 | sed "s#^$HERMES_HOME_PATH/##" | sort

sqlite3 "$HERMES_HOME_PATH/state.db" ".tables"
sqlite3 "$HERMES_HOME_PATH/response_store.db" ".tables"
sqlite3 "$HERMES_HOME_PATH/a2ui_state.db" ".tables"
```

注意：`state.db`、`sessions/`、`response_store.db`、`logs/`、`pastes/`、`cache/` 都可能间接包含用户输入、工具输出、代码片段、日志、token 或隐私数据。做归档、发给别人或提交 issue 前，要先脱敏。
