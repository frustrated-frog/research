# JDT Hermes Agent - 改造目标

## 背景

我们决定以 `Hermes Agent` 作为主底座，建设一个可持续演进的通用智能体系统，而不是继续以 `jd-agent-chat-ui` 作为主战场。

`jd-agent-chat-ui` 后续定位为领域资产仓，主要提供 A2UI 相关的协议、组件元数据、校验规则、测试样例和 benchmark 参考，不再承载通用智能体底座的主线演进。

## 总目标

- 基于 Hermes 构建一个可扩展的通用智能体底座。
- 底座优先具备 memory、compression、skill、MCP、hook、delegation、API server 等通用能力。
- A2UI JSON 生成和编辑能力不再作为系统核心架构，而是作为智能体的扩展能力接入。
- 未来无论是页面生成、页面编辑、设计稿转页面，还是更复杂的代码与工具协作任务，都尽量走同一套通用智能体底座。

## 核心原则

- 复用 Hermes 已有能力，避免重写核心循环。
- JD 定制尽量放在扩展层，不轻易侵入 Hermes 内核。
- 只迁移真正有价值的 A2UI 领域资产，不迁移旧系统的强耦合主编排。
- 先把底座跑顺，再接具体业务能力。
- A2UI 只是一个能力域，不再成为整个系统的中心。

## 第一阶段目标

第一阶段的目标不是复刻现有 `/api/chat` 业务接口，而是先吃透 Hermes 源码并明确改造切入点。

这一阶段需要完成：

- 熟悉 Hermes 的源码结构和运行链路。
- 搞清楚 agent 主循环、tool 调用、hook 生命周期、memory provider、context compression、skill 安装与调用、MCP、delegation、API server、runs/SSE 的实现方式。
- 明确哪些能力 Hermes 已经具备，哪些地方需要 JD 扩展层补充。
- 形成一份稳定的改造边界和实施顺序，避免一开始就把 A2UI 逻辑硬塞进主循环。

## 第二阶段目标

在 Hermes 底座理解清楚并稳定后，再开始落地 JD 扩展层。

预期扩展形态：

- `plugins/jd_a2ui/`：A2UI 插件入口
- `skills/jd-a2ui-*`：A2UI 生成、编辑、设计风格、组件约束等 skill
- `hooks/jd-*`：线程初始化、上下文预热、压缩后续链校验等 hook
- `mcp/jd-design-context/`：设计上下文读取适配层
- `cli/` 或调试命令：A2UI 校验、预览、诊断、调试

## 底座能力目标

需要重点确认并逐步增强的底座能力包括：

- 长期记忆
- 短期记忆
- 线程/会话持久化
- 超长上下文压缩
- 压缩后目标不漂移
- skill 安装、启用、升级、卸载
- MCP 接入与工具发现
- hook 生命周期扩展
- delegation / subagent
- API server 的 runs / SSE

## A2UI 能力目标

A2UI 相关能力后续要做成智能体可调用的能力包，而不是写死在主流程中。

目标能力包括：

- 生成 A2UI JSON
- 编辑已有 A2UI JSON
- 根据图片或设计稿生成页面
- 基于组件 meta、schema、validator 做约束生成
- 基于设计上下文做更高质量的 UI grounding
- 基于 skill、MCP、hook、CLI 的组合完成 UI 任务

## 资产迁移边界

从 `jd-agent-chat-ui` 只迁移下面这些领域资产：

- A2UI JSON schema
- 组件 meta / catalog
- 编辑 patch 规则与最小 diff 逻辑
- validator / safety 规则
- 代表性测试样例
- benchmark 脚本

不迁移下面这些旧主链强耦合逻辑：

- 现有 `/api/chat` 主编排
- requirement planner 主路径
- runtime-only 状态机壳层
- 针对旧接口流程写死的调度逻辑

## 当前明确不做的事情

- 第一阶段不追求立即兼容旧版 `/api/chat` 接口文档。
- 第一阶段不追求把 A2UI 页面质量一次做到最好。
- 第一阶段不把 `jd-agent-chat-ui` 整仓迁入 Hermes。
- 第一阶段不轻易改写 Hermes 的核心 conversation loop。

## 阶段验收标准

第一阶段验收标准：

- 我们能够清楚说明 Hermes 的核心模块分工。
- 我们能够明确指出 JD 扩展层应该放在哪里。
- 我们有一份清晰的实施顺序，而不是边写边试错。
- 我们知道后续接入 A2UI 时，哪些能力走 skill，哪些走 MCP，哪些走 hook，哪些需要 CLI。

第二阶段验收标准：

- JD 扩展层可以在 Hermes 中被稳定加载。
- 通用底座能力可运行，且具备后续承载 A2UI 的能力。
- A2UI 作为一个能力域被接回系统，而不是反过来绑架系统结构。

## 当前任务清单

当前我们先做两件事：

1. 熟悉 Hermes 源码项目。
2. 在熟悉源码的基础上，确定第一刀最稳的改造切入点。

在此之前，不急于大规模编码改造。
