# jdt-hermes-agent 分支与上游同步约定

## 目标

- 保留 Hermes 上游历史，便于持续同步 `NousResearch/hermes-agent`
- 将 JD 定制与上游同步解耦，避免后续能力开发污染同步基线
- 为 memory / plugin / A2UI / design-context 等能力改造提供稳定开发面

## 远端约定

- `upstream`: `https://github.com/NousResearch/hermes-agent.git`
- `origin`: `git@coding.jd.com:mkt-campaign/jdt-hermes-agent.git`

## 分支分层

### 1. `upstream-sync`

- 只用于同步 Hermes 上游最新代码
- 目标是尽量保持与 `upstream/main` 对齐
- 不承载 JD 业务开发

### 2. `jd/main`

- JD 内部稳定主线
- 所有对外可交付、可回归、可发布的 JD 能力都先沉淀到这里
- 上游同步结果先进入 `upstream-sync`，确认稳定后再合入 `jd/main`

### 3. 功能分支

- 一律从 `jd/main` 切出
- 用于承载具体能力开发，例如：
  - `feature/memory-...`
  - `feature/plugin-...`
  - `feature/a2ui-...`
  - `feature/design-context-...`

## 开发约束

- 不在 `upstream-sync` 上直接做 JD 定制开发
- 不在 `main` 上直接开发
- 新功能、新实验、新修复，都从 `jd/main` 切功能分支

## 推荐同步流程

1. 更新上游：
   - `git fetch upstream`
2. 切到同步分支：
   - `git checkout upstream-sync`
3. 快进同步 Hermes：
   - `git merge --ff-only upstream/main`
4. 切回 JD 主线：
   - `git checkout jd/main`
5. 评估并合入同步结果：
   - `git merge upstream-sync`
6. 从 JD 主线切功能分支：
   - `git checkout -b feature/<topic>`
