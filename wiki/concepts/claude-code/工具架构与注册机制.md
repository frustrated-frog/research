# 工具架构与注册机制

> Claude Code 工具系统是 Agentic 能力的核心基础设施

## 核心类型架构

三个核心类型构成整个工具系统：

| 类型 | 作用 |
|------|------|
| **ToolDef** | 部分定义，允许只实现核心功能 |
| **Tool** | 完整工具，包含 ~40 个方法 |
| **buildTool()** | 将 ToolDef 补全为 Tool，自动填充安全默认值 |

```typescript
export type Tool = {
  name: string
  inputSchema: Input                    // Zod 参数 Schema
  checkPermissions(): Promise<PermissionResult>  // 权限检查
  call(): Promise<ToolResult>           // 核心执行逻辑
  renderToolUseMessage()                // UI 渲染
  description() / prompt()              // 提示生成
  isConcurrencySafe(): boolean          // 并发安全性
  isReadOnly(): boolean                 // 是否只读
  isDestructive?(): boolean            // 是否破坏性
}
```

## 工具注册三层架构

```
getAllBaseTools()           →  50+ 内置工具列表
        ↓
getTools(permissionContext) →  模式过滤 + 权限过滤 + 启用检查
        ↓
assembleToolPool()          →  合并 MCP 工具 + 去重
```

### 工具分类

| 类型 | 来源 | 示例 |
|------|------|------|
| **内置工具** | 编译时定义 | FileReadTool, BashTool, GrepTool |
| **MCP 工具** | 运行时动态发现 | 外部 MCP 服务器提供 |

## 工具过滤四维度

| 维度 | 机制 | 示例 |
|------|------|------|
| **模式过滤** | Simple/REPL/Coordinator 模式 | Simple Mode 只保留 3 个核心工具 |
| **权限过滤** | blanket deny 移除 | `Bash(rm *)` 被完全禁止 |
| **特性标志** | feature() 检查 | `MonitorTool` 需要 `feature('MONITOR_TOOL')` |
| **Agent 限制** | 白/黑名单 | Sub-Agent 不能使用 TaskOutputTool |

## 工具生命周期

```
定义 → 注册 → 过滤 → 提示生成 → 执行
 1. ToolDef 对象      4. tool.prompt() 生成
 2. buildTool()       5. validateInput → checkPermissions → call()
 3. getAllBaseTools()
```

## 工具开发最佳实践

1. **Schema**：使用 `lazySchema()` 避免循环依赖
2. **权限检查**：正确返回 `PermissionResult`，`isConcurrencySafe` 只在无副作用时 true
3. **UI 渲染**：实现 `renderToolUseMessage` + `renderToolResultMessage`
4. **性能**：长时间运行工具支持 `onProgress` 回调，支持中断

## MCP 工具集成

MCPTool 作为模板，在 `mcpClient.ts` 中动态实例化：
- 支持延迟加载（`shouldDefer`）+ 强制加载（`alwaysLoad`）
- 权限格式：`mcp__<server>__<tool>` 或 `mcp__<server>__*`
- 与内置工具共享权限检查和 UI 渲染框架
