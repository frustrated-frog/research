# 权限模型与审批流程

> Claude Code 安全体系的核心——Allow/Ask/Deny 三级权限体系 + 六层规则优先级

## 三种权限裁决

| 裁决 | 含义 | 典型场景 |
|------|------|---------|
| **Allow** | 自动放行 | 白名单命令、只读操作 |
| **Ask** | 弹出确认框 | 未知命令、敏感文件 |
| **Deny** | 直接拒绝 | 被禁命令、禁止路径 |

## 六层规则优先级（高→低）

```
session > cliArg > command > projectSettings > userSettings > policySettings
```

每层维护三个规则数组：`alwaysAllowRules`、`alwaysAskRules`、`alwaysDenyRules`

## 规则格式

- 工具级：`Bash`、`Read`、`Edit`
- 命令级：`Bash(git *)`、`Bash(npm install)`
- 路径级：`Edit(src/**)`
- MCP：`mcp__server__*`

## 权限检查六步流水线

1. **全局拒绝检查** — blanket deny 匹配
2. **全局允许检查** — blanket allow 匹配
3. **工具自身检查** — tool.checkPermissions()
4. **Hook 拦截** — PreToolUse hooks
5. **Ask 规则检查** — 匹配则返回建议更新
6. **权限模式判定** — default/plan/auto/bypass

## 权限模式

| 模式 | 行为 |
|------|------|
| **default** | 敏感操作逐一确认 |
| **plan** | 只能读不能写，探索专用 |
| **auto** | AI 分类器自动决策 |
| **bypass** | 跳过所有检查（沙箱环境） |

## Auto Mode 安全防护

1. **危险规则剥离**：空白 `Bash` 规则会被移除
2. **分类器评估**：两阶段（Fast Stage + Thinking Stage）
3. **失败保护**：API 失败回退到 Ask 模式
4. **熔断机制**：连续拒绝触发 fallback

## 死循环防护

```
DENIAL_LIMITS = {
  maxDenialsPerTool: 3,      // 同一工具连续拒绝上限
  cooldownPeriodMs: 30000,    // 冷却期 30 秒
}
```

连续拒绝达上限时，向 AI 注入系统消息要求改变策略。
