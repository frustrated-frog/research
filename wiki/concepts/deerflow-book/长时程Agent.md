# 长时程 Agent

**长时程 Agent（Long-horizon Agent）** 是 DeerFlow 核心设计的起点——一种能够完成复杂、多步骤、跨越数十轮交互而不出错的 AI Agent 类型。与简单的"问答式"AI 不同，长时程 Agent 必须像一位经验丰富的项目经理一样：理解宏观目标、规划执行步骤、在遇到挫折时自我修正、最终交付完整成果。

## 定义：三个核心特征

DeerFlow 的源码文档（`chapters/01-what-is-deerflow.md`）明确指出，长时程 Agent 具有三个缺一不可的特征：

### 1. 多步骤执行能力（Multi-step Execution）

复杂任务天然地无法在单次交互中完成。以"帮我分析竞品"为例：这个任务需要——搜索多个竞品信息、抓取详细内容、整理对比数据、生成报告——至少 10 个以上独立的操作步骤。模型必须能够生成一系列逻辑连贯的步骤，并正确执行它们。

这听起来理所当然，但实践中极难实现。原因在于：每一步的输出会成为下一步的输入，上下文中任何一个环节的疏漏（误解、幻觉、工具调用错误）都会级联放大，最终导致任务失败。

### 2. 工具使用能力（Tool Use）

Agent 必须能够调用外部工具来完成单靠文本生成无法实现的任务：搜索网页、读写文件、执行代码、调用 API。工具的多样性和可靠性直接决定了 Agent 能力的边界。

DeerFlow 的内置工具集覆盖了文件系统操作、命令执行、Web 搜索、图片查看、文件呈现等核心能力，并通过 MCP 扩展机制支持任意外部服务的接入。

### 3. 自我修复能力（Self-correction）

当执行过程中出现错误时，Agent 必须能够识别问题（"刚才那个搜索没有返回结果"）、分析原因（"可能是关键词不够精确"）、调整策略（"换一个搜索角度重试"）并重新执行。这是"智能"与"死板执行"的本质区别。

DeerFlow 通过多种机制支持自我修复：ReAct 循环中的观察-推理-行动模式、错误消息作为上下文反馈给模型、以及 ClarificationMiddleware 允许 Agent 在遇到不确定情况时主动向用户提问。

## 与简单 Agent 的本质区别

| 维度 | 简单 Agent | 长时程 Agent |
|------|-----------|-------------|
| 交互模式 | 单轮问答 | 多轮迭代 |
| 上下文依赖 | 无状态，每次独立 | 状态跨轮持久 |
| 错误处理 | 返回错误结束 | 识别、分析、重试 |
| 任务分解 | 一次性输出全部结果 | 分步执行，每步验证 |
| 执行时间 | 秒级 | 可能数十分钟 |

## DeerFlow 如何实现长时程 Agent

DeerFlow 的整个架构都是围绕长时程 Agent 的需求设计的：

**上下文管理**：通过多层中间件（SummarizationMiddleware、MemoryMiddleware、TodoMiddleware）确保上下文在长时程执行中不会膨胀失控，同时关键状态（任务列表）不会因摘要压缩而丢失。

**文件系统作为外部存储**：遵循"内存-磁盘"分层原则，大量中间数据写入 `/mnt/user-data/` 而非塞进上下文，只有真正需要的信息才保留在消息历史里。

**Sub-Agent 并行分解**：当任务过于复杂时，Lead Agent 可以将子任务委派给 Sub-agent 并行执行，既利用了并发优势，又通过独立的执行环境隔离了上下文膨胀。

**持久化 Checkpointer**：异步 Checkpointer 将 Agent 的完整执行状态（包括消息历史、中间变量、artifacts）持久化到磁盘，即使进程重启也能恢复执行。

## 小结

长时程 Agent 是 DeerFlow 区别于简单 AI 助手的核心概念。它不是某一两个具体功能的集合，而是一种系统设计哲学——围绕"复杂任务需要多步骤、工具、修复"这三个需求，构建从底层执行引擎到上层提示词工程的完整基础设施。理解这个概念，是理解 DeerFlow 所有其他设计的起点。
