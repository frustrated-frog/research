# 置信度阈值

**置信度阈值（Confidence Threshold）** 是 DeerFlow 长期记忆系统中一个看似简单但至关重要的设计参数——它决定了新抽取的 Fact（事实）必须有多"确定"才能被写入 `memory.json`。设置为 0.7，意味着 LLM 判定置信度低于 70% 的信息不会被写入长期记忆。

## 在记忆更新流程中的位置

理解置信度阈值，需要先理解 DeerFlow 记忆更新的完整流程（详见[[entities/deerflow-book/记忆系统]]）：

1. 对话结束后，`MemoryMiddleware` 捕获过滤后的对话消息
2. 消息进入 `MemoryUpdateQueue`，等待 30 秒防抖
3. `MemoryUpdater` 调用 LLM，从对话中抽取可能需要记忆的 Fact
4. LLM 返回 JSON 格式的 Fact 列表，每个 Fact 带有 `confidence` 分数
5. **只有 `confidence >= 0.7` 的 Fact 才会被写入 `memory.json`**

第 5 步的判断发生在 `_apply_updates()` 方法中：

```python
def _apply_updates(self, existing_memory, new_facts):
    for fact in new_facts:
        if fact.confidence < 0.7:
            continue  # 跳过置信度不足的 Fact
        # ... 写入逻辑
```

## 为什么需要显式阈值而非全量写入

最直观的替代方案是"对话中提到的所有信息都写入记忆"。但这样做有两个严重问题：

**第一，噪音积累。** 用户可能在不同对话中提到大量临时性、试探性的想法——"我在考虑学 Python"、"我想了解一下 Rust"——这些并非真正的用户特征，写入后会污染记忆质量。置信度阈值提供了一个过滤层，确保只有"足够确定"的信息才进入长期记忆。

**第二，LLM 的过度泛化。** LLM 有时会从单次对话中过度推断用户特征。比如用户说"我最近在学 Go"，LLM 可能生成置信度 0.5 的 Fact"用户是 Go 开发者"——这个推断在单句话基础上置信度不足，0.7 阈值将其过滤。多次会话、多个证据累积后，同一推断的置信度才会达标，写入记忆。

## 0.7 这个数字是怎么来的

0.7 不是科学计算的结果，而是工程实践中的经验值：

- **低于 0.6**：过于宽松，几乎所有推断都会被写入，噪音问题重现
- **高于 0.85**：过于严格，真正的用户特征需要多次验证才能达标，导致记忆"跟不上"用户变化
- **0.7 附近**：在"及时捕捉用户特征"和"避免过度泛化"之间取得了较好平衡

这是一个典型的"超参数"——系统提供了一个可配置的默认值（`DEFAULT_CONFIDENCE_THRESHOLD = 0.7`），管理员可以通过 `config.yaml` 调整：

```yaml
memory:
  confidence_threshold: 0.75  # 调高：更保守，只记最确定的
  # confidence_threshold: 0.6  # 调低：更激进，记住更多
```

## 置信度 vs. 证据数量

LLM 生成的 `confidence` 分数本质上是主观判断——模型根据当前对话内容推断"这个信息有多可靠"。但 DeerFlow 还通过 `source` 字段（记录来源 thread_id）支持跨会话的证据累积。

假设用户在不同会话中两次提到"我在学 Go"：

- 第一次：LLM 生成 Fact `{content: "在学习 Go", confidence: 0.6}` → 被阈值过滤，未写入
- 第二次：LLM 看到历史记忆中有"在学习 Go"，且新旧信息一致 → 生成 `confidence: 0.85` → 通过阈值，写入

这种机制让置信度成为一个动态累积的分数——越常被提及的信息越"可信"。

## 阈值与 Fact 淘汰的交互

当 `memory.json` 中的 Fact 数量超过 `max_facts` 上限时（默认 100 条），`MemoryUpdater` 会根据以下规则淘汰：

1. **同类别优先保留**：已存在的高置信度 Fact 不会被同类低置信度 Fact 替换
2. **时间因素**：长期未更新的 Fact 优先级降低
3. **置信度排序**：淘汰时优先移除最低置信度的 Fact

置信度阈值在这个淘汰机制中扮演双重角色——既是 Fact 写入的门槛，也是 Fact 淘汰时的优先级依据。

## 小结

置信度阈值是 DeerFlow 记忆系统的"噪音过滤器"。0.7 这个经验值在捕获用户特征和避免过度泛化之间取得了平衡，而跨会话的证据累积机制让真正重要的信息最终能够突破阈值写入记忆。理解这个设计，有助于你在实际使用中判断：为什么某些信息没有被记住，以及是否需要调整阈值来适应特定场景。
