# 仓库即事实来源

**仓库即事实来源（Repository as Source of Truth）** 是 harness 工程的核心原则：代码仓库作为项目决策、架构约束、执行状态和验证标准的权威信息源。仓库外面说的不算。

## 问题背景

Agent 的输入只有三样东西：
1. 系统提示和任务描述
2. 仓库里的文件内容
3. 工具执行的输出

你的 Slack 历史、Jira 工单、Confluence 页面、工程师脑子里的隐性知识——agent 全都看不到。

## 知识可见性缺口

项目总知识中不在仓库里的比例。缺口越大，agent 失败的概率越高。

检验方法——冷启动测试：
1. "这是什么系统？" → AGENTS.md / README
2. "怎么组织的？" → ARCHITECTURE.md
3. "怎么跑？" → Makefile / init.sh
4. "怎么验证？" → 测试、lint、check 命令
5. "现在做到哪了？" → PROGRESS.md / 功能清单

能回答几个，地图就画了几分。

## ACID 类比

把数据库事务管理原则用到 agent 状态管理：
- **原子性**：每次逻辑操作用一个 git commit
- **一致性**：定义"一致状态"的验证谓词
- **隔离性**：多 agent 并发用独立进度文件或 git 分支
- **持久性**：关键知识用 git 跟踪的文件持久化

## 知识衰减率

仓库中单位时间内变得过时的知识条目比例。文档和代码脱节是最大敌人——比没有文档更危险。
