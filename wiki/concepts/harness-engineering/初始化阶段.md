# 初始化阶段

**初始化阶段** 是 agent 生命周期中的第一个阶段，不做功能实现，只建立后续所有实现阶段的执行前提。核心原则：先打地基，再砌墙。

## 问题背景

把初始化和实现混在一起的典型后果：
- Agent 花了 80% 精力写功能代码，剩下 20% 随便搭基础设施
- 测试框架配了但没验证过
- 进度文件没创建
- 第一个会话不明显，第二个会话就暴露了

初始化和实现的优化目标完全不同：
- **实现阶段目标**：最大化已验证功能的数量和质量
- **初始化阶段目标**：最大化后续所有实现的可靠性和效率

## 自举契约

项目能被全新 agent 会话无歧义操作的条件，四个条件缺一不可：
1. **能启动**：环境可运行
2. **能测试**：示例测试通过
3. **能看进度**：进度文件存在
4. **能接手下一步**：任务清单存在

## 初始化验收清单

```markdown
## 初始化验收清单
- [ ] `make setup` 从零开始能成功
- [ ] `make test` 至少有一个测试通过
- [ ] 新的 agent 会话能只看仓库回答"怎么跑"和"怎么测"
- [ ] 任务分解文件存在且有至少 3 个任务
- [ ] 所有内容已提交到 git
```

## 热启动 vs 冷启动

- **冷启动**：从空目录开始，agent 要猜项目结构
- **热启动**：从模板或已有项目开始，基础设施已经就位

热启动效果远好于冷启动——就像在有水电的工地上开工，比在荒郊野岭从头搞起快得多。

## 数据支撑

Anthropic 数据：使用独立初始化阶段的项目，多会话场景中的功能完成率比混合方式高 31%。关键是——初始化阶段投入的时间在后续 3-4 个会话中就能完全收回。
