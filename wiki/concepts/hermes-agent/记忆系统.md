# 记忆系统

> 两层持久化记忆（MEMORY.md/USER.md）+ 外部记忆提供者插件

## 两层核心记忆

### MEMORY.md — Agent 的工作笔记

- **容量**：2,200 字符（~800 tokens）
- **内容**：环境事实、项目约定、工具特性、所学教训
- **例子**："这台服务器运行 Debian 12，Docker 24.0，SSH 端口 2222"

### USER.md — 用户画像

- **容量**：1,375 字符（~500 tokens）
- **内容**：用户偏好、沟通风格、姓名/时区、工作习惯
- **例子**："用户叫小明，后端工程师，喜欢简洁回复"

## Entry 数据结构

内存中是 `List[str]`，持久化到文件时用 `§`（段落符号 U+00A7）连接：

```
Debian 12，Docker 24.0
§
用户偏好 TypeScript，不喜欢 any
```

选择 `§` 的原因：在中英文文本中极少出现，不干扰 frontmatter 解析。

## 原子写入

**问题**：`open("w")` 会先截断文件为 0 字节，写入中途其他进程读取会得到空文件。

**解决**：临时文件 + `os.replace()` 原子替换。
```
1. 写到同目录临时文件（.mem_xxx.tmp）
2. fsync 强制刷盘
3. os.replace() 原子替换目标文件
```
读者要么看到旧内容，要么看到新内容，绝不会看到截断状态。

## 文件锁

多个 Hermes 实例同时运行时防止写-写冲突：

```python
# 单独的 .lock 文件（不锁主文件，否则原子replace失效）
with _file_lock(lock_path):
    entries = _reload_target()   # 重新读，处理其他进程的写入
    entries.append(content)      # 修改
    _write_file(path, entries)   # 原子写入
```

## 冻结快照

会话期间，系统提示中的 memory 内容**固定不变**，即使工具调用写入了新条目。只有下一会话 `load_from_disk()` 时才更新。

**为什么这样做**：防止 prefix cache 失效。每次 memory 写入若重建系统提示，Anthropic cache breakpoint / OpenAI cached tokens 全部重新计算。

**两套状态并行**：
- 实时状态（工具调用修改）→ 立即落盘
- 冻结快照（注入系统提示）→ 会话期间不变

## 操作方式

| 操作 | 说明 |
|------|------|
| add | 添加条目（自动安全扫描 + 容量检查） |
| replace | 用子字符串匹配定位后修改 |
| remove | 用子字符串匹配定位后删除 |

**不需要 Entry ID**：用自然语言子字符串匹配，LLM 直接说"把提到 dark mode 的那条改成 light mode"即可。

## 容量耗尽处理

当 memory 满了，返回当前所有条目，让 LLM 决定合并或删除哪个，然后重试。

## 外部记忆提供者

8 个插件可选择启用，与内置记忆共存：
- **Honcho**：辩证式用户建模，跨会话深化用户模型
- **Mem0**：语义记忆
- **OpenViking**：知识图谱
- **Hindsight**：自动事实提取
- **Holographic / ByteRover / RetainDB / Supermemory**：记忆增强

外部提供者只能选一个（防止工具名冲突和结果不一致）。

## 会话搜索 vs 固定记忆

| | 固定记忆 | 会话搜索 |
|--|--|--|
| 容量 | ~1,300 tokens 合计 | 无限（所有会话） |
| 速度 | 即时（系统提示中） | 需要搜索 + LLM 摘要 |
| 用途 | 始终可用的关键事实 | "上周讨论过X吗" |
| 管理 | LLM 人工策展 | 自动记录所有会话 |

## 最佳实践

**应该写入**：
- 用户偏好："偏好 TypeScript，不喜欢 any"
- 环境事实："服务器 Debian 12，PostgreSQL 16"
- 雷区："不要对 Docker 命令用 sudo，用户在 docker 组"
- 约定："项目用 tabs，120字符行宽"

**不应写入**：
- 模糊信息："用户问过 Python"（太模糊）
- 易重新发现的事实：可网络搜索获取的
- 大段原始数据：代码、日志、数据表
- 临时会话内容
