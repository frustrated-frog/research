# Claude Code 架构全景分析

> 综合 27 篇源码解读文档的全局视角分析

## 核心定位再理解

Claude Code 的本质是一个 **Agentic Loop 引擎**，而非简单的 AI 聊天工具。它：

1. **拥有完整的 shell 访问权** — 能做任何用户在终端里能做的事
2. **自主决策工具调用链** — 不只是问答，而是多步推理和执行
3. **在本地运行** — 低延迟、高隐私、不依赖 IDE

这与 Cursor/GitHub Copilot 等 IDE 集成工具形成本质区别。

## 架构设计的核心思想

### 分层解耦

五层架构每层职责明确、边界分明：
- 交互层变化不影响核心循环
- 工具层扩展不触动编排逻辑
- 通信层切换 provider 不需要改上层代码

### 流式优先

整个系统从入口到出口都是流式的：
- API 通信：端到端流式响应
- 工具执行：StreamingToolExecutor 在 API 流式接收期间就开始执行
- UI 渲染：实时增量渲染，无需等待完整响应

### 安全纵深

```
权限系统（应用层） + 沙箱系统（OS 层）= 双重保险
```

## 数据流全景

```
用户输入
    ↓
REPL.tsx processUserInput()
    ↓
QueryEngine.submitMessage()
    ↓ recordTranscript()（早期持久化）
    ↓
query() AsyncGenerator
    ├→ 上下文预处理（压缩/budget）
    ├→ deps.callModel() → API 流式响应
    ├→ StreamingToolExecutor.execute()
    │   ├→ validateInput()
    │   ├→ checkPermissions()
    │   └→ tool.call()
    └→ needsFollowUp? → continue / return
    ↓
QueryEvent stream → UI 更新
```

## 关键设计亮点

| 设计 | 价值 |
|------|------|
| State 对象封装 | 避免 9 个独立可变变量，代码清晰 |
| 早期持久化 | 进程被杀也能通过 `--resume` 恢复 |
| 延迟揭示 | 可恢复错误先重试再报告，用户体验更好 |
| 工具并发安全标记 | 自动区分读写操作，并发执行降延迟 |
| 拒绝追踪 | 防止 AI 死循环重试同一被拒操作 |

## 与其他 Agent 框架的对比启示

Claude Code 的设计反映了一些重要原则：

1. **工具是 Agent 的边界** — 工具定义的质量决定 Agent 能力上限
2. **安全不是事后添加** — 权限和沙箱从第一天就融入架构
3. **流式优于批处理** — 端到端流式带来更好的实时性和更低延迟
4. **配置优于硬编码** — 多层配置系统支持不同信任级别的灵活部署
