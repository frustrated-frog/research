# Runtime-Independent Persistent Agents：运行时独立持久智能体

**来源**：Zhenyu Zhao、Roy Zhao，*Runtime-Independent Persistent Agents: Preserving Identity, Memory, and Code Across Models, Harnesses, and Servers*。参考实现 Enoch 的证据冻结于 2026-08-31 的 commit c8013ed249bc11bc13f3843ed0f0cb9729f858c1。

## 核心命题

[原文事实] 论文把长期 Agent 的连续性承担体定义为 \(P=(I,M,B)\)：架构身份、私有耐久记忆／工作流状态、有版本的可执行 body；将推理器、harness、宿主定义为可替换执行底座 \(E=(R,H,D)\)，将 chat、API 等定义为可替换交互面 \(S\)。替换 \(E\) 或 \(S\) 并在授权协议下保持谱系与续接权，是迁移而不是新建 Agent（PDF 第 1–4 页）。

论文区分：

- **授权系统连续性**：身份、状态、body 谱系与唯一续接授权满足架构不变量；
- **行为身份保真度**：迁移后执行是否能回忆、组合、践行该身份。

[原文事实] 本文仅为前者给出实现与机制证据，明确没有报告后者的 benchmark 或行为迁移结果（第 1、6–7 页）。

## 可复用机制

- 六阶段迁移：quiesce/fence → checkpoint → validate → bind → rehydrate → verify/resume；
- 六个不变量：身份与谱系、记忆祖先、body revision、唯一协作 authority、显式 capability delta、运行时标签不覆盖安装身份；
- provider-neutral contract：portable core 不直接依赖 Telegram、Codex、GitHub、launchd 等 provider-native 语义；
- 外部副作用：intent + idempotency key + fencing epoch；不能 reconcile 或幂等重放的 provider 应 fail closed；
- 私有 state 与可复用 body 分开保管，迁移 manifest 记录版本和 hash，secret 可只记录目标凭据引用。

## 实证边界

[原文事实] 冻结的 Enoch snapshot 在 clean-room 中报告 833 个 core tests 与独立执行的 92 个 provider/library tests；有 Telegram/Slack、launchd/systemd 两类 reference，实现了 state migration/rollback、authority handoff/fencing 等机制，并观察到 reasoner-version、interaction-surface、host-machine 的单轴替换（第 5–6 页，表 2–3）。

[作者解释] 这些结果支持机械可替换性、故障处理与单轴可行性；不能支持跨模型行为不变、性能／成本／时延等价、外部 provider 安全或受控的全轴组合迁移。
