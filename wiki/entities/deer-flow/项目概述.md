## 1. 项目定位

DeerFlow（**D**eep **E**xploration and **E**fficient **R**esearch **Flow**）是字节跳动开源的 **Super Agent Harness**。它不是一个单纯的 AI 聊天机器人，而是一个完整的 Agent 运行时框架——将 sub-agents、memory、sandbox 和可扩展的 skills 有机组合，让 Agent 能够完成几乎任何事情。

**核心理念**：从 Deep Research 工具进化为 Super Agent Harness，让开发者可以"拿走即用"或"拆解定制"。

**开源地址**：https://github.com/bytedance/deer-flow
**官网**：https://deerflow.tech

### 两种运行模式

| 维度 | 标准模式 | Gateway 模式（实验性） |
|------|---------|----------------------|
| 架构 | Gateway (REST) + LangGraph (Agent Runtime) | Gateway 内嵌 Agent Runtime |
| 并发控制 | `--n-jobs-per-worker` per worker（需 License） | `--workers` × async tasks（无单 worker 上限） |
| 进程数 | 4（frontend, gateway, langgraph, nginx） | 3（frontend, gateway, nginx） |
| 资源占用 | 较高（两个 Python 运行时） | 较低（单一 Python 运行时） |
| LangGraph License | 生产环境必需 | 不需要 |

## 3. 核心子系统

### 3.1 Agent 系统

**Lead Agent** 是整个框架的运行时入口，通过 `make_lead_agent(config)` 创建，结合：

- **动态模型选择**：支持 thinking/vision 的多模型配置
- **Middleware Chain**：9 个中间件按严格顺序执行
- **Tool System**：sandbox + MCP + community + 内置工具组合
- **Subagent 委托**：并行任务执行能力
- **System Prompt**：skills 注入、memory 上下文、工作目录引导

### 3.2 Middleware Chain（中间件链）

中间件按固定顺序执行，每个处理特定横切关注点：

| # | Middleware | 职责 |
|---|-----------|------|
| 1 | **ThreadDataMiddleware** | 创建线程隔离目录（workspace, uploads, outputs） |
| 2 | **UploadsMiddleware** | 注入新上传文件到对话上下文 |
| 3 | **SandboxMiddleware** | 获取代码执行的 sandbox 环境 |
| 4 | **DanglingToolCallMiddleware** | 注入缺失的 ToolMessages（用户中断时） |
| 5 | **GuardrailMiddleware** | 工具调用前的授权检查（可选） |
| 6 | **SummarizationMiddleware** | 接近 token 限制时压缩上下文（可选） |
| 7 | **TodoListMiddleware** | Plan 模式下的多步骤任务跟踪（可选） |
| 8 | **TokenUsageMiddleware** | Token 使用量追踪（可选） |
| 9 | **TitleMiddleware** | 首轮交互后自动生成对话标题 |
| 10 | **MemoryMiddleware** | 异步对话记忆提取队列 |
| 11 | **ViewImageMiddleware** | 为视觉模型注入 base64 图像数据（条件触发） |
| 12 | **SubagentLimitMiddleware** | 强制 `MAX_CONCURRENT_SUBAGENTS` 限制（可选） |
| 13 | **LoopDetectionMiddleware** | 检测并中断重复工具调用循环 |
| 14 | **ClarificationMiddleware** | 拦截澄清请求并中断执行（必须最后） |

### 3.3 Sandbox 系统

**Per-thread 隔离执行环境**，带虚拟路径翻译：

- **抽象接口**：`execute_command`, `read_file`, `write_file`, `list_dir`
- **提供者**：
  - `LocalSandboxProvider`（文件系统）
  - `AioSandboxProvider`（Docker 隔离，community 模块）
- **虚拟路径映射**：
  - Agent 视角：`/mnt/user-data/{workspace,uploads,outputs}`
  - 物理路径：`backend/.deer-flow/threads/{thread_id}/user-data/...`
- **工具**：`bash`, `ls`, `read_file`, `write_file`, `str_replace`

### 3.4 Subagent 系统

- **内置 Agent**：
  - `general-purpose`：完整工具集
  - `bash`：命令执行专家（仅在 shell 可用时暴露）
- **并发控制**：每轮最多 3 个 subagent，15 分钟超时
- **执行流**：`task()` tool → `SubagentExecutor` 后台线程 → 轮询 5s → SSE 事件 → 返回结果

### 3.5 Memory 系统

**跨会话持久化上下文保留**：

- **自动提取**：分析对话获取用户上下文、事实和偏好
- **结构化存储**：用户上下文、历史、置信度评分事实
- **防抖更新**：批量更新，最小化 LLM 调用
- **存储**：JSON 文件（`backend/.deer-flow/memory.json`）

### 3.6 Skills 系统

- **格式**：目录结构，包含 `SKILL.md`（YAML frontmatter）
- **加载**：递归扫描 `skills/{public,custom}` 下的 `SKILL.md`
- **注入**：启用的 skills 在 agent system prompt 中列出
- **安装**：`POST /api/skills/install` 从 `.skill` ZIP 压缩包提取

### 3.7 MCP 系统

- 使用 `langchain-mcp-adapters` 的 `MultiServerMCPClient`
- **懒加载**：首次使用时通过 `get_cached_mcp_tools()` 加载
- **缓存失效**：通过 mtime 检测配置文件变更
- **传输方式**：stdio、SSE、HTTP
- **OAuth 支持**：`client_credentials`、`refresh_token`

### 3.8 IM Channels 系统

支持飞书、Slack、Telegram 与 Agent 的桥接：

- **架构**：通过 `langgraph-sdk` HTTP 客户端与 LangGraph Server 通信
- **消息流**：外部平台 → Channel 实现 → `MessageBus.publish_inbound()` → 调度 → LangGraph Server → 响应

## 4. 技术栈

| 层级 | 技术 |
|------|------|
| Agent 框架 | LangGraph (1.0.6+), LangChain (1.2.3+) |

| 前端 | Next.js (Node.js 22+) |
| 反向代理 | Nginx |

## 5. 配置系统

### 5.1 主配置 (`config.yaml`)

- `models[]`：LLM 配置（类路径、thinking/vision 支持）
- `tools[]`：工具定义（模块路径和分组）
- `tool_groups[]`：工具逻辑分组
- `sandbox.use`：Sandbox 提供者类路径
- `skills`：Skills 目录路径
- `title`：自动标题生成
- `summarization`：上下文摘要设置
- `subagents`：Subagent 系统开关
- `memory`：Memory 系统设置

### 5.2 扩展配置 (`extensions_config.json`)

- `mcpServers`：MCP 服务器配置
- `skills`：Skill 启用状态

## 6. 安全设计

- **本地可信环境优先**：默认仅通过 127.0.0.1 访问
- **沙箱隔离**：代码执行在 Docker 容器或 Kubernetes Pod 中
- **Guardrails**：可选的工具调用授权层
- **IM 渠道认证**：支持按用户白名单

## 8. 关键特性

- ✅ **Subagent 并行执行**：复杂任务分解为多个子任务并行处理
- ✅ **Thread 隔离**：每个对话线程拥有独立的文件系统和记忆
- ✅ **Skills 热插拔**：无需重启即可启用/禁用技能
- ✅ **多 IM 渠道**：飞书/Slack/Telegram 无缝接入
- ✅ **Context Engineering**：主动上下文压缩和摘要
- ✅ **LangSmith/Langfuse 链路追踪**
- ✅ **Embedded Python Client**：无 HTTP 服务的进程内使用
