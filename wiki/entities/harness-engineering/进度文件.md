# 进度文件

**进度文件（PROGRESS.md）** 是 agent 的"日记本"——记录已完成工作、进行中工作、已知问题和下一步行动，让下一个会话能快速接上。

## 在系统中的位置

```
项目目录/
├── PROGRESS.md              ← 每次会话结束时更新
├── DECISIONS.md             ← 设计决策日志（可选）
└── features.md              ← 功能清单（状态机）
```

## 核心结构

```markdown
# 项目进度

## 当前状态
- 最新 commit: abc1234 (feat: add user preferences endpoint)
- 测试状态: 42/43 通过 (test_pagination_edge_case 失败)
- Lint: 通过

## 已完成
- [x] 用户模型和数据库迁移
- [x] 基础 CRUD 端点
- [x] 认证中间件集成

## 进行中
- [ ] 分页功能 (90% - 边界条件测试失败)

## 已知问题
- test_pagination_edge_case 在空结果集时返回 500
- 需要确认是否要在列表中包含已删除用户

## 下一步
1. 修复分页边界条件 bug
2. 添加"是否包含已删除用户"的查询参数
3. 更新 API 文档
```

## 工作流程

### 会话开始时（上班打卡）
1. 读 PROGRESS.md 了解当前状态
2. 读 DECISIONS.md 了解重要决策
3. 跑 make check 确认仓库处于一致状态
4. 从 PROGRESS.md 的"下一步"部分继续工作

### 会话结束时（下班打卡）
1. 更新 PROGRESS.md
2. 跑 make check 确认一致状态
3. 提交所有已完成的工作

## 关键指标

**重建成本**：新会话恢复到可执行状态所需的时间。好 harness 能把重建成本从 15 分钟压到 3 分钟。
