# 中间件管道（Middleware Pipeline）

**中间件管道** 是 DeerFlow 扩展和定制 Agent 行为的核心架构——11 个中间件依次串联，每个中间件在消息流入（before_model）、模型调用（wrap_model_call / after_model）、Agent 执行（before_agent / after_agent）三个时机对状态进行读取、检查、修改或注入。所有中间件加起来，构成了从"用户输入"到"Agent 输出"的完整处理流水线。

## 中间件的执行时机

LangChain 的 `BaseMiddleware` 定义了 5 个钩子，DeerFlow 的中间件覆盖了其中 4 个：

```
MessageInput
    ↓
before_agent(state, runtime)     ← ThreadDataMiddleware, UploadsMiddleware,
    ↓                              SandboxMiddleware, DanglingToolCallMiddleware
[LangGraph: Model 推理]
    ↓
before_model(state, runtime)    ← TodoMiddleware
after_model(state, runtime)     ← SubagentLimitMiddleware
    ↓
after_agent(state, runtime)      ← SummarizationMiddleware, TitleMiddleware,
    ↓                              MemoryMiddleware, SandboxMiddleware,
MessageOutput                       ClarificationMiddleware
```

### 各钩子的语义

- **`before_agent`**：Agent 执行前调用，可修改 state 或 runtime.context（如注入元信息、初始化沙箱）
- **`before_model`**：模型推理前调用，可向 messages 注入内容（如丢失的任务列表提醒）
- **`after_model`**：模型推理后、工具执行前调用，可修改模型输出（如截断超额的工具调用）
- **`after_agent`**：Agent 执行完成后调用，可处理执行结果（如捕获对话用于记忆、生成标题）

## 11 个中间件详解

### ThreadDataMiddleware

**时机**：`before_agent` | **作用**：注入 thread_id、user_id 等元信息

在 `runtime.context` 中设置必要的标识符，供其他中间件和工具函数使用。

### UploadsMiddleware

**时机**：`before_agent` | **作用**：注入用户上传文件的内容

将用户上传的文件内容块 `<uploaded_files>...</uploaded_files>` 注入到消息历史开头，让 Agent 在开始执行前就知道用户提供了什么材料。

### SandboxMiddleware

**时机**：`before_agent` + `after_agent` | **作用**：管理沙箱的获取和释放

```python
def before_agent(self, state, runtime):
    if not self._lazy_init:
        sandbox_id = self._acquire_sandbox(thread_id)
        return {"sandbox": {"sandbox_id": sandbox_id}}

def after_agent(self, state, runtime):
    sandbox_id = ...
    get_sandbox_provider().release(sandbox_id)
```

`lazy_init=True`（默认）时，`before_agent` 不做任何事，实际获取推迟到第一次工具调用。

### DanglingToolCallMiddleware

**时机**：`after_model` | **作用**：修复中断导致的悬空工具调用

当用户中断对话时，消息历史中可能残留有 `AIMessage(tool_calls=[...])` 但缺少对应的 `ToolMessage`。这个中间件自动插入占位 ToolMessage，防止 LLM API 报格式错误。

### TodoMiddleware

**时机**：`before_model` | **作用**：摘要压缩后恢复任务列表

`SummarizationMiddleware` 截断旧消息时，可能把 `write_todos` 工具调用也截没了。`TodoMiddleware` 检测这种情况，将当前 `state["todos"]` 重新注入上下文，防止 Agent "遗忘"当前任务。

### SubagentLimitMiddleware

**时机**：`after_model` | **作用**：截断超额的任务委派调用

检查最后一次 AI 消息中的 `tool_calls`，如果 `task` 调用数量超过 `max_concurrent`（默认 3），只保留前几个，其余静默丢弃。防止 LLM 一次生成过多 Sub-agent 导致系统过载。

### SummarizationMiddleware

**时机**：`after_agent` | **作用**：自动压缩过长的消息历史

LangChain 内置中间件，DeerFlow 通过 `SummarizationConfig` 配置触发阈值（messages / tokens / fraction 三种模式）和保留策略。

### TitleMiddleware

**时机**：`after_agent` | **作用**：生成会话标题

当用户第一次发起对话时，从首轮交互中提取关键信息，生成一个简洁的会话标题。

### MemoryMiddleware

**时机**：`after_agent` | **作用**：捕获对话用于长期记忆

过滤对话（只保留 human/ai 消息，清洗上传文件痕迹），将对话上下文推入 `MemoryUpdateQueue`，触发异步的记忆更新流水线。

### ViewImageMiddleware

**时机**：`after_agent` | **作用**：管理多模态图片注入

将 `view_image` 工具产生的 base64 图片数据合并到 `state["viewed_images"]`，供前端渲染。

### ClarificationMiddleware

**时机**：`after_agent` | **作用**：处理用户的澄清回复

检测到 `ask_clarification` 工具被调用时，中断正常的执行流，将控制权交还给 Gateway，等待用户输入澄清信息后再恢复 Agent 执行。

## 中间件的组合顺序

`_build_middlewares()` 按以下顺序串联：

```python
middlewares = [
    ThreadDataMiddleware(),
    UploadsMiddleware(),
    SandboxMiddleware(lazy_init=lazy_init),
    DanglingToolCallMiddleware(),
    TodoMiddleware(),
    SubagentLimitMiddleware(),
    SummarizationMiddleware(config=summarization_config),
    TitleMiddleware(),
    MemoryMiddleware(agent_name=agent_name),
    ViewImageMiddleware(),
    ClarificationMiddleware(),
]
```

**顺序敏感的原因**：`SandboxMiddleware` 在 `before_agent` 时注入 sandbox 状态，后续中间件和工具函数才能使用。`DanglingToolCallMiddleware` 必须在模型调用后立即修复格式错误。`TodoMiddleware` 在 `before_model`（模型推理前）运行，所以放在 `SummarizationMiddleware`（`after_agent`）之后仍然能正确检测到丢失的任务列表。

## 自定义中间件

DeerFlow 的中间件基于 LangChain 的 `BaseMiddleware`，任何继承自 `AgentMiddleware[AgentState]` 的类都可以插入管道：

```python
class MyCustomMiddleware(AgentMiddleware[AgentState]):
    def before_agent(self, state, runtime) -> dict | None:
        # 自定义逻辑
        return {"custom_field": "value"}
```

通过修改 `create_agent()` 的 `_build_middlewares()` 调用即可注入自定义中间件，无需修改框架核心代码。

## 小结

中间件管道是 DeerFlow 的"神经网络"——11 个中间件各司其职，覆盖了从元信息注入、文件处理、沙箱管理、错误修复、任务列表维护、并发控制、上下文摘要、标题生成、记忆捕获、图片管理到澄清处理的完整流程。每个中间件职责单一、可独立测试、可按需替换，共同构成了一个可观测、可扩展、可维护的 Agent 行为调控系统。
