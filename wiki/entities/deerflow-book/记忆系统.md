# 记忆系统（Memory System）

**记忆系统** 是 DeerFlow 的长期记忆基础设施——在每次对话结束后自动分析对话内容，将用户的关键信息提取并持久化到 `memory.json` 文件，供未来的对话使用。随着使用时间的增长，DeerFlow 会越来越了解用户，产出越来越个性化的帮助。

## 核心设计

记忆系统要解决的核心问题：**如何让 Agent 跨会话记住用户是谁、偏好什么、在做什么，同时避免记忆文件中堆积无用信息？**

DeerFlow 的答案是**三层记忆架构 + 置信度阈值 + 防抖更新**。

## 数据结构：memory.json

记忆持久化在 `memory.json` 中，结构如下：

```json
{
  "version": "1.0",
  "lastUpdated": "2026-03-12T10:30:00Z",
  "user": {
    "workContext": {
      "summary": "字节跳动后端开发工程师，主要使用 Go 和 Python",
      "updatedAt": "2026-03-12T10:30:00Z"
    },
    "communicationStyle": {
      "summary": "偏好简洁的回复",
      "updatedAt": "2026-03-10T08:00:00Z"
    }
  },
  "topOfMind": {
    "summary": "正在研究 DeerFlow 记忆系统，计划下季度迁移 CI/CD",
    "projects": [
      {
        "name": "DeerFlow Wiki",
        "description": "为 DeerFlow 0.3 编写完整中文源码解析"
      }
    ],
    "updatedAt": "2026-03-12T10:30:00Z"
  },
  "facts": [
    {
      "id": "fact_abc123",
      "content": "在字节跳动担任后端开发工程师",
      "category": "context",
      "confidence": 0.95,
      "createdAt": "2026-03-12T10:30:00Z",
      "source": "thread_abc123"
    }
  ]
}
```

三层各有不同的语义和更新策略（详见[[concepts/记忆三层架构]]）。

## 更新流水线

```
对话结束
    ↓
MemoryMiddleware（捕获对话）
    ↓
MemoryUpdateQueue（30秒防抖）
    ↓
MemoryUpdater（LLM 抽取 + 合并写入）
    ↓
memory.json（原子写入）
```

### 第一步：MemoryMiddleware 捕获对话

`MemoryMiddleware.after_agent()` 过滤对话消息，只保留 human 和 ai 消息，清洗上传文件痕迹：

```python
# 过滤掉工具调用消息，只保留原始交互
filtered_messages = _filter_messages_for_memory(messages)
# 清洗 <uploaded_files> 块，防止 Agent 记住不存在的文件路径
```

### 第二步：MemoryUpdateQueue 防抖

`MemoryUpdateQueue` 维护一个内存队列，每次 `add()` 调用重置 30 秒定时器。30 秒内没有新对话，才触发处理：

```python
def add(self, thread_id, messages, agent_name):
    # 同一 thread_id 的旧条目被替换
    self._queue = [c for c in self._queue if c.thread_id != thread_id]
    self._queue.append(context)
    self._reset_timer()  # 重置 30 秒定时器
```

防抖的意义：避免每次用户发一条消息就触发一次 LLM 调用，批量处理更高效。

### 第三步：MemoryUpdater LLM 抽取

`MemoryUpdater.update_memory()` 调用 LLM，从对话中抽取需要记忆的信息：

```python
# 1. 读取当前 memory.json
existing = get_memory_data()
# 2. 格式化对话
conversation = format_conversation_for_update(messages)
# 3. 构建 Prompt（当前记忆 + 新对话）
prompt = MEMORY_UPDATE_PROMPT.format(memory=existing, conversation=conversation)
# 4. 调用 LLM，返回 JSON 更新指令
new_facts = llm.invoke(prompt)
# 5. 应用更新（置信度过滤 + 合并）
_apply_updates(existing, new_facts)
# 6. 原子写入
_save_memory_to_file(existing)
```

### 原子写入

`memory.json` 的写入采用"写临时文件 + rename"模式，保证数据一致性：

```python
temp_path = file_path.with_suffix(".tmp")
with open(temp_path, "w", encoding="utf-8") as f:
    json.dump(memory_data, f, indent=2, ensure_ascii=False)
temp_path.replace(file_path)  # 原子操作
```

### mtime 缓存

`get_memory_data()` 维护一个内存缓存，读取文件前先检查 mtime：

```python
if mtime == file_path.stat().st_mtime:
    return _memory_cache[agent_name]  # 直接返回缓存
# 否则重新读取
```

避免重复读取磁盘。

## 配置

`config.yaml` 中的记忆配置：

```yaml
memory:
  enabled: true
  max_facts: 100            # facts 上限
  confidence_threshold: 0.7 # 置信度阈值
  debounce_seconds: 30      # 防抖延迟
```

## 上下文注入

`format_memory_for_injection()` 将 `memory.json` 格式化为注入文本：

```python
def format_memory_for_injection(memory_data) -> str:
    # 输出格式：
    # ## 关于你
    # - 工作背景：...
    # - 当前焦点：...
    # ## 我知道的事
    # - fact1（来源：..., 置信度：高）
```

这些文本通过 `apply_prompt_template()` 注入到 System Prompt 的 `<memory>` 块中。

## 与中间件的关系

记忆系统与其他中间件有密切配合：

- **UploadsMiddleware**：清洗上传文件痕迹，防止 Agent 记住不存在的路径
- **TodoMiddleware**：如果对话涉及任务列表的更新，`memory.json` 会记录这些变化
- **SummarizationMiddleware**：摘要截断后，`MemoryMiddleware` 只捕获剩余可见的消息，避免将截断部分重复记忆

## 小结

记忆系统是 DeerFlow 真正实现"越来越懂用户"的核心——三层记忆架构分离了不同类型的信息，置信度阈值过滤了噪音，防抖机制节省了 LLM 调用，原子写入保证了数据安全。从对话捕获到 LLM 抽取、再到合并写入和上下文注入，整条流水线完全异步，不会阻塞用户的交互体验。理解记忆系统，是理解 DeerFlow 如何实现个性化、持续改进的 AI 协作体验的关键。
